## 実装順と所有範囲

この作業の実装担当が`skills/orch/`を一括して更新する。全体フローとの接続は`skills/devlow/`、設計と実装状況は`docs/`に反映する。既存の他スキル・テンプレートの変更は保持する。

1. レビュー修正：入力版を変えない通常再開、有効な検証記録だけの提出、旧通知の失効、統括セッションの引き継ぎ条件。
2. unit・試行・状態・保存のテストと実装。
3. 依存、検証、提出、受け入れ、通知、gateのテストと実装。
4. CLI・bootstrap・TSV出力とリポジトリ外での動作確認。
5. スキル手順、全体フロー接続、文書とコードの整合性確認。

正本はJSON、TSVは出力とする。実行時の外部依存は追加せず、Bunと標準APIを使う。CLIの具体的な入力仕様は配布用の参照資料へ記す。

## 検証記録

実装と確認を完了した。環境はmacOS、Bun 1.4.2、TypeScript 7.0.2。入口は`skills/orch/scripts/task.ts`。18種類の台帳更新、10種類の問い合わせ、exportを提供する。

### 実装した責務

- unitの親子・担当・工程・依存を登録し、進行状態、条件別判定、提出の受け入れを分離した。レビューの報告完了と対象の不合格を併存できる。
- 契約・依存入力を開始時に固定する。同じ版だけ通常再開でき、前提変更・担当交代・やり直しは新attemptにする。置き換え済みの合格や、異なる版の同じ対象を提出に混ぜない。
- 提出・通知・操作履歴を同じJSON更新で保存する。再開時は旧提出と未処理完了通知を失効させ、履歴を残す。親の受け入れ前に後続へ進めない。
- 担当・session・attempt・versionを照合し、operation-idの同一再送を重複実行しない。統括セッションの復旧は停止・権限根拠を持つassignに限定する。根拠、入力、実行者、影響unitを履歴から辿れる。
- 排他、一時保存、fsync、renameで保存する。残存ロック、未知schema、壊れたJSONを上書きしない。statusとdoctorは読み取り専用、exportは同じrevisionのTSV・Markdownを生成する。
- 利用者向けの運用手順とCLI入力をorchに置き、全体フローとtask-templateから参照する。task.md本文、checkpoint、OKFはCLIの状態と分離した。

skipは既存OKFの上流Go実行ファイルとの互換テスト2件で、`OKF_REFERENCE_BIN`未指定によるもの。orchにskipはない。CLIはテストを記録するだけなので、この開発時のテスト結果を利用先の台帳へ転記していない。

振る舞いのテストを先行し、最初の9ケースが未実装で失敗することを確認してから実装した。追加確認では、置き換え済み記録の再利用、統括交代後に残る旧session、引き継ぎ根拠の欠落、開始前の確認記録、入力変更後の判定表示、同一対象の版の混在を失敗として再現し、修正後の成功を確認した。

保存の確認には並行更新、古いversion、保存直前の例外、実プロセスをcommit前にSIGKILLした場合を含む。SIGKILL後も保存済みJSONを読め、残存ロックを診断でき、停止を確認してロックを取り除いた後に更新できた。電源断や別OSを検証したという意味ではない。

リポジトリ外へscriptsをコピーし、初回・2回目の起動、依存定義変更、ロック欠落時の拒否、ローカル依存の固定導入とlockfile変更後の再導入を実CLIで確認した。利用先のpackage.json・bun.lockを変更せず、準備ファイルはスキルのscripts内へ、台帳は利用先へ保存された。

### 独立した利用検証

system skill-creatorのforward testing手順に基づき、実装担当とは別のエージェントが、コピーしたSKILL.md・参照資料・--helpだけを読んでCLIを操作した。実装コードと開発用テストは読ませず、親子のactor/sessionは一時プロジェクトで順次模擬した。

初回は親＋調査＋レビュー、依存待ち、報告受け入れ、中断、担当交代、新試行、親の統合、TSV出力を67回のCLI操作で確認した。3unitがcompleted・acceptedとなり、未処理通知は0。期待する拒否として、受け入れ前の開始、旧sessionの更新、不合格記録を省いた提出も確認した。

この検証で、ルートunitを統括担当がacceptする手順の不明瞭さと、assignの停止根拠が履歴に残らない問題を発見した。両方を修正後、新しいコピーで36回のCLI操作を行い、履歴から根拠・ハッシュを辿れることと、ルートの完了通知を処理できることを確認した。追加の不明点はなかった。

詳細な一時記録は`/tmp/orch-forward.jQxHjU/`と`/tmp/orch-retest.kMOWtk/`の報告書・commands.jsonlにある。これらは一時領域であり、永続的な実施結果と修正判断は本節に保持する。実エージェントをCLIで並列起動・停止した検証ではない。

## 実装時に具体化した点と残る範囲

Bun 1.4.2は外部依存が空の場合に空のlockfileを保持しない。空のlockfileを手書きしてもfrozen installで拒否されたため、架空の依存は追加せず、ゼロ依存では依存定義とランタイム版を検査するbootstrapとした。依存を追加する場合はscripts内の実lockfileで固定導入する。この条件を配布設計に明記し、両経路を検証した。

台帳は同じホストのローカルファイルを対象にする。大量のunit・長期履歴に対する性能、ネットワーク共有、別OS、電源断、自動アーカイブは未確認または対象外。外部成果物の版、担当の実際の停止、証拠の十分さは担当が確認する。CLIの成功やファイルの存在だけでは証明しない。

配布生成・マーケットプレイスのインストール、OKF CLIの依存配置移行、実際の業務案件での長期運用は残る。今回の完了はorchの配布用ソース、全体フロー接続、上記範囲の実行確認である。
