# main公開時のCLI起動競合の修正

2026-09-23。mainへ公開後の[最初のCI](https://github.com/sori883/agent-gear/actions/runs/35853656563)で、orchの同時初回起動テストが失敗した。終了コードだけでは原因が分からなかったため、標準出力・標準エラーも比較するようにし、[再実行](https://github.com/sori883/agent-gear/actions/runs/35854091686)で依存パッケージの読み込み失敗を確認した。

あるプロセスが依存未導入の状態で起動し、そのbootstrap確認前に別プロセスが導入を終えると、導入済みマーカーを見た先行プロセスは再起動を省いていた。Bun 1.4.2は同プロセス内の読み込みで未導入時の解決結果を使う場合がある。macOS上で通常の同時起動を100回繰り返しても再現しなかったが、先行プロセスを標準入力で待機させ、別プロセスの導入完了後に解放すると同じ失敗を再現できた。

orchとOKFの公開入口は、bootstrapの確認・必要な導入を終えてから、専用のrun.tsを新しいBunプロセスで実行する。導入済みの場合もこの境界を保ち、本体を起動済みプロセス内へ読み込まない。作業ディレクトリ、引数、標準入出力、終了コード、JSONエラー形式を保持する。通常起動にも子プロセス1回分の費用が加わるため、従来の短時間の性能測定値を修正後の値として扱わない。外部依存を持たないsetupは今回の対象外とした。

両CLIに順序を固定した回帰テストを追加した。orchでは修正前の失敗と修正後の成功を確認した。配布物の版数を0.1.0+codex.20260923112621へ更新し、両製品の配布物236ファイルを正本から生成した。

macOS arm64・Bun 1.4.2で全体テスト156成功・既存の上流比較2件スキップ・失敗なし、型検査、配布物の全ファイル照合、両製品のマニフェスト検証、差分の空白検査が成功した。リモートの結果は修正コミットに紐づくGitHub Actionsで確認する。
